# 版本发布完整流程指南

> **重要提示**: 这是基于v2.0.0发布经验总结的完整流程，用于避免遗漏关键步骤

## 📋 完整发布流程检查清单

### 阶段1: 版本更新准备
- [ ] 更新 `package.json` 中的版本号
- [ ] 更新所有UI组件中显示的版本号 (如 `SettingsPanel.jsx`)
- [ ] 测试应用功能确保无重大bug
- [ ] 运行发布前统一抽检: `npm run verify`
- [ ] 运行构建命令生成最新安装包

### 阶段2: Git提交和标签
- [ ] 检查git状态: `git status`
- [ ] 添加所有更改: `git add .`
- [ ] 提交代码更改: `git commit -m "🚀 发布版本 X.X.X"`
- [ ] 推送到远程: `git push origin main`
- [ ] 创建版本标签: `git tag -a vX.X.X -m "版本发布说明"`
- [ ] 推送标签: `git push origin vX.X.X`

### 阶段3: 发行文档创建 ⚠️ **关键步骤**
- [ ] 创建 `RELEASE_NOTES_vX.X.X.md` 发行说明文件
- [ ] 创建 `GITHUB_RELEASE_GUIDE_vX.X.X.md` 创建指南文件
- [ ] **重要**: 检查git状态确认新文件: `git status`
- [ ] **重要**: 提交文档文件: `git add *.md && git commit -m "📝 添加vX.X.X发行版文档"`
- [ ] **重要**: 推送文档: `git push origin main`

### 阶段4: GitHub发行版创建
- [ ] 访问GitHub仓库发行版页面
- [ ] 选择已创建的版本标签
- [ ] 填写发行版标题和描述
- [ ] 上传安装包文件
- [ ] 发布正式版本

## 🚨 常见遗漏点记录

### 问题1: 发行文档未提交 (v2.0.0实际遇到)
**症状**: 创建了发行说明文件，但在git提交后才创建，导致文件未被包含在仓库中

**原因**: 流程顺序错误，先提交代码再创建文档

**解决方案**: 
1. 检查未追踪文件: `git status`
2. 添加遗漏文件: `git add RELEASE_NOTES_*.md GITHUB_RELEASE_GUIDE_*.md`
3. 单独提交文档: `git commit -m "📝 添加发行版文档"`
4. 推送更新: `git push origin main`

**预防措施**: 在阶段3中明确检查和提交文档文件

### 问题2: 版本号不一致
**症状**: package.json和UI显示的版本号不匹配

**解决方案**: 使用查找替换确保所有文件中的版本号一致

### 问题3: 安装包文件缺失或过期
**症状**: artifacts/dist-electron 目录中没有最新版本的安装包

**解决方案**: 在提交前运行 `npm run dist:win` 确保生成最新安装包

## 🔄 自动化命令序列

### 完整发布命令序列 (复制粘贴使用)

```powershell
# 1. 检查当前状态
git status

# 1.1 发布前统一抽检
npm run verify

# 2. 添加所有更改
git add .

# 3. 提交代码更改 (替换X.X.X为实际版本号)
git commit -m "🚀 发布版本 X.X.X

✨ 新功能：
- [描述新功能]

🐛 修复：
- [描述bug修复]

📝 文档：
- [描述文档更新]"

# 4. 推送代码
git push origin main

# 5. 创建并推送标签 (替换X.X.X和发布说明)
git tag -a vX.X.X -m "版本 X.X.X 发布说明"
git push origin vX.X.X

# 6. ⚠️ 创建发行文档后，检查并提交
git status
git add RELEASE_NOTES_*.md GITHUB_RELEASE_GUIDE_*.md
git commit -m "📝 添加vX.X.X发行版文档"
git push origin main

# 7. 验证安装包存在
Get-ChildItem "artifacts/dist-electron\*X.X.X*" | Select-Object Name, Length, LastWriteTime
```
